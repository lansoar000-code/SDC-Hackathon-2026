# 项目要实现的效果
## 一次完整使用过程（计划）
1. 餐厅准备按日期、菜品记录的历史销售数据。
2. 导入数据，系统提示缺失、重复或不合理的记录。
3. 选择预测日期，填写天气、是否考试周、是否有当地活动。
4. 点击预测，页面显示每道菜预计需求、合计需求和备餐参考。
5. 可以查看历史预测；以后录入实际销量，与预测比较并展示误差。

## 第一版优先做
- 保留已有页面的天气、考试周和活动输入。
- 增加预测日期，明确预测的是哪一天。
- 前后端连通，前端能展示等待、成功和失败状态。
- 从简单预测基线开始；模拟演示和真实数据预测必须有明显标识。
- 历史数据校验，按菜品预测，保存预测记录。
- 展示菜品级需求和总量；备餐建议与预测销量分开解释。

## 后续扩展（建议，尚未确认）
- 历史趋势图、实际销量反馈、误差报表和导出。
- 自动天气数据、账号、多餐厅管理、库存或采购联动。
第一版不依赖这些扩展才能演示。最终页面范围、算法、技术框架、部署方式仍待定。
