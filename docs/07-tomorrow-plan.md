# 2026-10-22 开发顺序
今天先理解各板块；本次只补说明和注释占位。

1. 确定演示范围、真实数据来源、菜品和数据格式；确认 Python 框架。
2. 让 backend/main.py 启动服务，完成健康检查；让前端 api.js 能访问它。
3. 完成数据库表、历史数据导入和校验；先能看到校验报告。
4. 完成简单预测基线，保证时间顺序正确、没有用到未来销量。
5. 接通预测请求，让页面展示每道菜、合计和数据来源。
6. 保存并查询预测记录，处理数据不足、错误输入和服务失败。
7. 用可用数据评估，再决定是否训练更复杂模型；有时间再加历史图和导出。
8. 在 develop 联调，稳定后合入 main；队友据实际功能制作报告、PPT、视频。

## 第一轮完成的判断
用户能够提交条件，后端返回有明确来源的结果，前端显示正确。
如果只有模拟数据，界面和材料都明确标为模拟，不把它说成真实模型成果。
