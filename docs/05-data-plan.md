# 数据字段与预测原则
## 历史销量表（建议字段）
| 字段 | 含义 | 是否必需 |
|---|---|---|
| date | 营业日期 | 是 |
| dish_id | 稳定的菜品编号 | 是 |
| dish_name | 菜名 | 是 |
| sales_quantity | 实际卖出份数，预测目标 | 是 |
| prepared_quantity | 实际备餐份数 | 可选 |
| waste_quantity | 剩余或浪费份数，口径需确认 | 可选 |
| weather | 当时天气 | 有可靠数据再用 |
| is_exam_week | 是否考试周 | 有可靠数据再用 |
| has_event | 是否有活动 | 有可靠数据再用 |

真实文件放 data/raw/，不能覆盖原始数据。清理结果放 data/processed/。当前未上传任何业务数据。
CSV/Excel 支持范围明天确定；不把手写样例当真实餐厅记录。

## 必须检查
- 日期可解析、数量非负、菜品编号稳定。
- 日期和菜品组合重复时提示，不自动叠加。
- 缺失日期不直接当作销量为零；先判断是否停业或缺记录。
- 若有备餐量，检查销量超过备餐等异常；浪费口径先确认。
- 历史特征只能读取目标日期之前的数据，按菜品分别计算。
- 预测当天的实际销量、实际浪费、实际备餐量不能当作已知输入。

## 模型与评估
先做历史均值等简单基线，再考虑 Ridge 或其他模型；最终算法尚未选定。
训练和验证按时间先后划分。记录 MAE（平均差多少份）、WAPE（整体相对误差）、Bias（偏多或偏少）。
WAPE 不能叫“准确率”；真实销量总和为零时要明确说明无法正常计算。
不引用旧项目指标作为当前仓库效果。代码现已支持训练与验证；当前检查使用合成测试数据，尚无真实餐厅评估结论。
