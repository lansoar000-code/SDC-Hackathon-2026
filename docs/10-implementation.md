# 2026-10-22 实现与验证
## 已实现
- FastAPI + SQLite，启动自动建表；同服务提供前端和 API 文档。
- UTF-8 CSV、第一张工作表 XLSX 导入；5 MB / 20,000 行限制；逐行错误，整批事务，重复数据不覆盖。
- 菜品查询、实际销量新增和分页查询。
- 明确选择的模拟演示、历史基线、按菜品训练的 Ridge，以及不优于基线时保留基线。
- 训练和在线共用特征，目标日/未来销量隔离；模型指纹变化回退基线。
- 预测条件、版本、数据截止日期、明细快照持久化；历史分页、详情与 CSV 导出。
- 预测销量与备餐建议分别显示；用户设定 0–50% 余量，用十进制计算后向上取整。
- 实际销量反馈、预测对比图和表；模拟记录不计入，补做历史预测明确标识。
- 五个编号脚本可独立运行；中文职责说明、统一代码格式与阅读指南。

## 验证证据
- 19 项 unittest 回归通过：原子导入与重复拒绝、非法 CSV、XLSX、字段约束、数据库重启持久化、模型实际选用与历史回退、未来销量隔离、特征隔离、备餐取整、CSV 导出、指标口径与文件隔离；补做历史预测不会覆盖事前指标。
- Ruff 检查和格式检查通过；前端模块语法检查通过。
- 五个编号脚本用独立合成数据完整执行：统一 CSV → 校验 → 训练 → 预测 CSV → 特征检查。
- 浏览器正常库验证无数据提示、明确模拟、保存记录。
- 浏览器独立验收库导入 84 条合成销量，完成训练比较、预测、10% 备餐余量、实际销量反馈和对比图表。
- 没有把验收数据库或合成销量提交为业务数据；测试样本生成器保存在 tests/。

## 不能据此声称
当前没有真实餐厅业务数据验证；合成样本通过说明流程和约束正常，不说明真实预测精度。
训练验证用于选模型，不是独立测试集；历史回放结果与事前预测分开。
天气、考试周、活动在基线模式不影响结果，模型模式的效果取决于这些历史字段是否存在、是否有足够变化。
