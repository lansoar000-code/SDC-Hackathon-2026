# 系统如何连接
```text
历史 CSV / Excel → 数据校验与清理 → 历史特征 → 训练及评估 → 模型文件
用户填写预测条件 → 前端请求 → 后端校验 → 预测服务 → 预测结果
                                                    ↓
                                           数据库保存记录
                                                    ↓
前端显示每道菜和合计 ← 后端返回统一格式的结果与来源标识
```

| 板块 | 输入 | 输出 |
|---|---|---|
| 前端 | 日期、天气、考试周、活动 | 请求及结果界面 |
| 路由 | HTTP 请求 | 参数校验后的服务调用、响应 |
| 业务服务 | 合法参数、历史数据 | 预测或导入结果 |
| 预测模块 | 过去销量、未来可知条件 | 每道菜需求估计 |
| 数据库 | 菜品、历史销量、预测记录 | 可查询记录 |
| 评估模块 | 按时间划分的真实销量与预测 | MAE、WAPE 等误差 |

离线训练：先用历史数据生成模型。在线预测：用户点击按钮时调用已有模型，不必每次重新训练。
技术方案建议：原生 HTML/CSS/JS + Python API + SQLite；具体 Python 框架明天确定，依赖文件暂不填版本。
