# 10,000 天合成食堂数据

## 数据身份与规模
这是虚构校园的模拟时间轴：1999-06-06 至 2026-10-21，共 10,000 个连续日期，8 道菜，每天每道菜一行，共 80,000 行。
不是 XMUM 或任何真实食堂的经营历史。全部菜品编号以 synth_ 开头，名称带 [SYNTHETIC]；预测页面会注明合成来源。

## 模拟假设
- 星期客流：周一至周五较高，周末下降。
- 示例校历：1、6、7、12 月为低客流假期；5、11 月 18 日起为考试阶段。均为虚构规则，不是官方校历。
- 年度维护：6 月 15 日关闭，所有菜品销量和备餐均为 0。共有 28 天关闭记录；它们不是缺失数据。
- 气候方向：参考 [METMalaysia 气候说明](https://www.met.gov.my/en/pendidikan/iklim-malaysia/) 中半岛部分地区的季节性降雨变化。
- 每日天气类别由带持续性的随机过程生成；雨天概率、天气对菜品的影响均为设计假设，不是天气观测或估计系数。
- 事件：随机安排少量已知活动，增加客流；考试对菜品偏好产生不同影响。
- 长期变化：模拟校园规模缓慢增加、部分菜品偏好变化；另加一段人为客流冲击及恢复期，日期由模拟序号决定，不对应真实防疫政策。
- 随机波动：共同客流扰动、菜品个别扰动、泊松计数波动。
- 备餐在随机需求实现之前制定，偶尔供给不足；售出=min(需求,备餐)，浪费=备餐−售出。

固定随机种子 20261022；实际生成使用 Python 3.12.14、NumPy 2.5.4。参数与每个 CSV 的 SHA-256 存 manifest.json。

## 文件
本地位置：data/synthetic/v1/。

| 文件 | 用途 |
|---|---|
| SYNTHETIC_sales_10000_days.csv | 全部菜品销量、备餐、浪费和可知条件 |
| import_batches/ | 4 个文件，每个 20,000 行，符合网页导入上限 |
| splits/train.csv | 最早 7,000 天：训练 |
| splits/validation.csv | 接下来 1,500 天：选择方法 |
| splits/test.csv | 最后 1,500 天：独立时间留出 |
| daily_context.csv | 每日汇总、校历、关闭日与模拟场景 |
| audit_oracle_NOT_FOR_TRAINING.csv | 潜在需求、未满足需求和售罄真值，仅用于审计 |
| training.sqlite3 | 独立合成数据数据库，不混入普通业务库 |
| holdout_report.json | 独立时间留出评估 |
| training_report.json | 评估和最终全量模型说明 |

完整 CSV 超过单次网页导入行数限制，手动导入时应依次使用四个导入包，而非整张大表。
GitHub 保存生成器、训练代码和说明；完整 CSV、数据库与模型由脚本在本地生成。

## 训练与结果
模型选择：前 7,000 天学习，接着 1,500 天验证；逐菜选择模型或基线，再用前 8,500 天重训。
测试：最后 1,500 天（12,000 条菜品记录）只评估，参数固定。每天可使用更早测试日已观察到的销量，属于滚动单日预测，不是一次预测未来 1,500 天。

| 方法 | MAE（份/菜品日） | WAPE（误差率） | Bias（份） |
|---|---:|---:|---:|
| 验证择优模型 | 12.1469 | 17.4458% | -0.6801 |
| 历史基线 | 14.5899 | 20.9545% | 0.1001 |

评估冻结后，另用全部 10,000 天生成 models/synthetic/v1/final_model.json。测试指标属于只训练至 2022-09-12 的 holdout_model.json，不能称为全量最终模型的独立测试结果。
备餐量、浪费量、审计潜在需求均不作为预测特征；目标是实际售出份数，售罄时可能低估潜在需求。
模型当前没有显式假期、关闭日和隐含供给冲击特征，这些会造成误差。模拟规律由作者设置，因此这里的成绩不能证明真实食堂效果。

## 运行
首次运行：python prepare_synthetic.py --end-date 2026-10-21。
输出目录已有文件时会停止，避免覆盖；再次生成请用 --output 和 --models 指定新目录。
运行 python run_synthetic.py 后访问 http://127.0.0.1:8002，使用独立的合成数据和最终模型。
普通 run.py 和 8000 端口仍使用原本数据库。
